# テスト構成

Mind Kernel MCP のテストは、責務に応じて以下のディレクトリ構成で管理されています。

## ディレクトリ構成

### `mind_kernel_mcp/tools`
**責務: 各ツールのロジック検証**

- 各ツールの内部ロジック、データ変換、エッジケース等を検証する単体テストです。
- 外部依存（GitHub API, DynamoDB 等）はすべてモック化されます。
- 高速に実行可能であるべきです。

### `integration`
**責務: 各ツールの IO (Input/Output) 検証**

- MCP サーバーの RPC ハンドラー (`handle_tools_call`) を介してツールを実行し、インターフェースの整合性を検証する統合テストです。
- クライアントからのリクエストパラメータ（`userId` 注入など）が正しくツールに渡り、期待するレスポンス構造が返却されるかを確認します。
- 外部依存はモック化しますが、サーバーのハンドラー層からツール層までのフローを結合してテストします。

### `scripts`
**責務: 各ツールの手元での動作確認**

- 実際に動作する環境（LocalStack, 実際の GitHub API 等）に対してリクエストを送信するスクリプト群です。
- 開発者が手元で動作確認を行う際や、E2E に近い形での検証に使用します。
- 実行には `make up` による環境構築や、適切な環境変数（`MCP_API_KEY` 等）の設定が必要です。
- CI では環境依存で失敗する可能性があるため、自動実行対象外
